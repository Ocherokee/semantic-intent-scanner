# v0.10: Contract and Boundary Hardening

v0.10 hardens existing deterministic interfaces without adding detectors, authority relationships, risk logic, or network behavior. Package and legacy report versions remain `0.4.0.dev0`; finding, inventory, change, and composite schemas remain independently versioned at `0.1`.

## Formal contracts

Draft 2020-12 schemas are published in `schemas/` for FindingContract, inventory, inventory change sets, and composite audits. Checked-in valid/invalid fixtures and `tests/test_contract_schema_parity.py` verify representative runtime/schema parity. Python validation remains authoritative for semantic and cross-record rules that JSON Schema cannot express faithfully: canonical URL equality, duplicate identities, deterministic ordering, change-type snapshot semantics, execution/finding count agreement, and finite Python float rejection. JSON itself cannot encode NaN or infinity; Python validators and serializers explicitly reject them.

## URL and origin profile

`scanner.url_normalization` is authoritative for guarded-fetch redirects, v0.6 inventory, v0.7 identity, and v0.8 trust boundaries; the inventory API retains compatibility wrappers. It accepts absolute HTTPS URLs only; rejects userinfo and malformed DNS labels; lowercases and IDNA-encodes hosts; removes one trailing host dot; compresses IP literals; removes default port 443 while preserving non-default ports; treats an empty path as `/`; removes literal RFC 3986 dot segments; preserves path case, query bytes, and percent-encoded path material; and excludes fragments. Encoded dot segments remain encoded and therefore do not acquire literal traversal semantics. Relative and scheme-relative declarations are resolved against the retrieved declaring URL before canonicalization. Redirects remain guarded hop-by-hop, and boundary comparisons use the same canonical scheme/host/port equivalence.

## Malformed structures

Malformed JSON/XML roots retain bounded `parse_error` metadata. Supported manifest and JSON OpenAPI declaration errors now retain field-specific bounded metadata rather than disappearing into a successful empty declaration set. OpenAPI server locations use `servers[index].url`; manifest authority fields retain their exact existing field names. Malformed MCP captures, inventories, change artifacts, and composite artifacts continue to fail visibly without creating synthetic security findings.

## Deterministic resource limits

| Boundary | Limit | Visible result |
|---|---:|---|
| fetched decompressed body | 512 KiB | observation `truncated` |
| redirects | 5 | failed fetch with bounded reason |
| inventory entries | 32 globally | inventory `truncated` |
| inventory traversal | depth 2 | no deeper fetch authorization |
| declarations per resource | 16 | bounded discovery |
| structured JSON document | 512 KiB | inventory `parse_error` + `resource_limit` |
| captured MCP file | 512 KiB | invalid input with byte-limit reason |
| MCP schema traversal | depth 64 / 4096 descriptions | malformed tool state |
| local skill/artifact file | 2 MiB | explicit invalid-input failure |
| directory-audited file | 1 MiB | finding states content was not analyzed |
| composite failure reason | 240 characters | normalized bounded reason |
| fetch connect/read timeout | 5 seconds per hop | failed observation |

Remote fetch DNS results are exhaustively checked before a pinned connection; the resolver controls the finite lookup response. Model input remains chunked by the existing evaluator. No silent truncation was added for security-relevant parsed structures.

## Locators and failures

Existing filesystem paths, remote URLs, MCP lossless JSON paths, inventory provenance, declaring/target origins, relationship types, and manifest fields remain machine-readable. v0.8 OpenAPI findings now preserve the exact `servers[index].url` trigger through existing evidence and context, requiring no FindingContract change.

Composite adapters isolate crashes, preserve successful siblings, bound and normalize public reasons, and keep semantic coverage explicit. Raw exception messages are not serialized by composite orchestration, guarded-fetch transport failures, DNS failures, or captured-MCP read/parse failures. Operational failure remains distinct from successful low-risk analysis; established exit codes and standalone output formats are unchanged.

## Credential boundary

All deterministic release-gating tests run without `ANTHROPIC_API_KEY` or any live model. Mock/fake-client tests cover judge orchestration, evidence boundaries, parsing, failure propagation, semantic coverage, and deterministic non-downgrade behavior. The eight credential-gated live Anthropic tests remain optional integration coverage for v0.11 CI planning.

## Explicit non-goals

This slice adds no detector, policy, composite score, fuzzy deduplication, network scheme, CI workflow, release automation, SARIF, OPA, or release-version change. It does not broaden OpenAPI/YAML parsing or execute discovered content.
