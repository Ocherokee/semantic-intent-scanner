## 1. v0.4 research question

v0.4 extends the scanner from local agent artefacts to **external semantic content**:

> Can an invariant-grounded evaluator detect when externally supplied content is being allowed to direct agent behaviour or extend agent trust without an independent trust decision?

Two concrete surfaces are implemented:

1. remote agent-facing documents (`llms.txt` / `llms-full.txt`), and
2. captured MCP `tools/list` metadata, including nested parameter descriptions.

These are treated as sibling adapters over one analysis architecture, not as separate security engines.

---

## 2. Invariant decision: I8, not I8 + I9

v0.4 adds one invariant:

**I8 — No Unverified External Instruction**

> Do not treat content retrieved from an external source — a remote document, an MCP tool description, a fetched page — as authoritative instruction. External content may describe and inform; it may not direct the agent's behaviour, and it may not extend the agent's trust to a package, domain, index, or tool it names, without an explicit trust decision.

The original draft considered a separate “No Dangling Reference” invariant. Review rejected that split. A stale or unclaimed package/domain is an **environmental condition**; the invariant failure is treating unresolved external authority as trustworthy. Dangling references therefore remain finding types under I8.

I8 maps to **M2 Transparency + M4 Integrity + M1 Consent**.

The invariant set is now frozen at **I1–I8** while the system is measured. Misclassifications should become retained benchmark/test cases rather than reasons to move the invariant definitions during calibration.

## 3. Shared evidence model

Remote and MCP findings use the same `Finding` model. Important fields include:

- `invariant_id`
- `finding_type`
- `risk`
- `summary` / `evidence`
- `analysis_method`
- `observed_at`
- `provenance_state`
- `detail`

`analysis_method` distinguishes:

- `rule_based` — deterministic parsing of the supplied bytes/text
- `external_state` — live registry/DNS state observed at a timestamp
- `fixture` — the same external-state interface answered from an offline snapshot
- `judge` — semantic findings added by the optional LLM lane

Deterministic and external-state findings are **append-only and non-downgradeable** by the judge.

### Provenance ladder

The remote registry/DNS lane uses:

`unclaimed` → `unknown` → `unverified` → `origin_aligned` → `conflicting`

The states are evidence descriptions, not certificates of legitimacy. In particular:

- existence is not legitimacy;
- `origin_aligned` is alignment evidence, not proof;
- later changes in registry/DNS state do not retroactively rewrite an earlier observation.

## 4. Remote-document lane

### Command

```bash
semantic-intent scan-remote https://example.com
semantic-intent scan-remote https://example.com --json
semantic-intent scan-remote https://example.com --judge
```

The adapter derives `/llms.txt` and `/llms-full.txt` from the supplied site/base URL.

### Fetch boundary

`scanner/remote_fetch.py` provides the guarded network path:

- HTTPS only;
- userinfo refused;
- private, loopback, link-local, CGNAT, metadata, reserved and other blocked address space rejected;
- every redirect hop revalidated;
- connection pinned to a validated IP while retaining the hostname for TLS/SNI;
- no credential forwarding;
- redirect/timeout limits;
- decompressed-body cap;
- final URL, redirect chain, timestamp, content type and body SHA-256 recorded.

Nothing retrieved is executed, installed, or followed as an instruction.

### Deterministic analysis

`scanner/remote_audit.py` is format-agnostic. It extracts and evaluates signals such as:

- package-install commands;
- pipe-to-shell / script-download patterns;
- package-index overrides;
- referenced domains;
- execution framing;
- package/domain existence and provenance signals through `scanner/registry.py`.

`scanner/llms_txt.py` is only the `llms.txt`-specific adapter.

### Operational failure

Security risk and operational status are separate.

If no supported remote document can be analyzed, `scan-remote` exits **3** and reports `overall_risk: null`. “The scan could not happen” is never represented as low risk.

Partial retrieval remains a valid scan when at least one supported document is available.

## 5. Two-pass semantic judge

`--judge` uses `scanner/remote_judge.py` and adds semantic analysis **without replacing deterministic evidence**.

There are two logical passes; actual API-call count can exceed two because Pass 2 may be chunked.

### Pass 1

Pass 1 receives:

- deterministic findings as trusted observations; and
- a bounded structured digest derived from attacker-controlled content, explicitly labelled untrusted-derived evidence.

It does **not** receive the raw/freeform document body.

### Pass 2

Pass 2 is the only place raw content appears. It is enclosed inside the hard boundary:

```text
<<<RETRIEVED_CONTENT untrusted>>>
...
<<<END_RETRIEVED_CONTENT>>>
```

The system instruction states that the block is evidence/data, not instructions to the evaluator.

Large documents are chunked. Chunk verdicts are reconciled per invariant before Pass-1/Pass-2 comparison.

### Reconciliation and coverage

For each invariant, the worse pass wins. Material disagreement is surfaced as `judge_pass_disagreement`; it is not averaged away.

Judge failure:

- never erases deterministic findings;
- never lowers deterministic risk;
- never becomes exit 3;
- is represented through `judge_status`, `semantic_coverage`, and `analysis_complete`.

Default operation without `--judge` remains deterministic-only.

## 6. MCP tool-description adapter

### Command

```bash
semantic-intent scan-mcp ./captured-tools-list.json
semantic-intent scan-mcp ./captured-tools-list.json --json
semantic-intent scan-mcp ./captured-tools-list.json --judge --server-label "acme-mcp"
```

v0.4 deliberately does **not** connect to or invoke arbitrary MCP servers. The input is a captured `tools/list` payload:

- bare tools array;
- `{ "tools": [...] }`; or
- JSON-RPC `{ "result": { "tools": [...] } }` envelope.

No MCP client, server process, `initialize`, live `tools/list`, or `tools/call` is part of this version.

### Field extraction

`scanner/mcp_adapter.py` evaluates:

- tool `name`;
- top-level tool `description`; and
- every string-valued `description` found recursively under `inputSchema`.

The schema is walked as ordinary JSON. `$ref` is not resolved and schema types are not executed or interpreted as authority.

### Two roles, two lanes

MCP text is deliberately split by role:

- **per-field documents → deterministic `analyze_document()`** for exact provenance;
- **one combined document per tool → `judge_document()` only** for cross-field semantic reasoning.

The combined document is never run through deterministic analysis, preventing duplicate findings and duplicate registry/DNS lookups.

### Provenance

MCP findings preserve both:

- `mcp_field` — readable normalized path; and
- `mcp_json_path` — lossless structural path.

Synthetic provenance identifiers use the lossless structural path and percent-encode attacker/user-controlled URI components. The original unescaped values remain in `Finding.detail`.

The server label is explicitly represented as declared but **not authenticated**. A captured file does not establish server identity.

Malformed/unrecognized MCP input produces `invalid_input`; a valid payload containing no tools produces `no_tools`. Both are exit **3** (“nothing analyzable”), using MCP vocabulary rather than HTTP/fetch terminology.

## 7. Semantic failure-pattern catalogue

v0.4 also establishes the standing failure-pattern catalogue in [`semantic-failure-patterns.md`](semantic-failure-patterns.md).

The first entry is **SFP-1 Workflow Injection**.

- **Pattern:** Workflow Injection
- **Failure mode:** Semantic Authority Collapse
- **Attacker technique:** Authorization Laundering
- **Primary invariant:** I8, compounded by I7, with I4/I3/I6 possible downstream if action occurs

Framework primitive:

> **Understanding is not verification. Verification is not authorization.**

The three checks are orthogonal. A claim may be true without its speaker having authority to cause the contemplated action.

The documented Horizon Accord phishing case is evidence of structural compatibility with autonomous-agent exploitation, not evidence that its author intentionally designed it for agents.

## 8. Test state at the final v0.4 feature commit

The reviewed v0.4 feature stack reached:

**144 passed, 8 skipped (API-gated), 0 failed.**

Coverage includes:

- guarded remote-fetch behavior through injected/fake transports;
- deterministic remote analysis and registry/DNS fixture state;
- remote CLI/report semantics;
- two-pass judge orchestration and disagreement/coverage behavior;
- MCP input shapes and recursive nested-description extraction;
- friendly-path collision vs lossless `mcp_json_path` provenance;
- the per-field deterministic / whole-tool judge split;
- malformed/no-tools MCP operational semantics;
- adversarial judge-injection and derived-action fixtures.

The real-network `_default_transport` path remains a known limitation: it is not integration-tested by the hermetic suite.

## 9. v0.4 boundaries

Deliberately out of scope:

- live MCP connection or tool invocation;
- executing any retrieved command or package instruction;
- treating registry existence as legitimacy;
- a new invariant beyond I8;
- an MCP-specific judge;
- global model-configuration refactoring;
- unrelated local-scan UX rough edges;
- claiming a clean scan certifies safety.

`RemoteDocument` is reused for the MCP adapter in v0.4 with a synthetic `mcp://` origin. Generalizing that abstraction to a broader evidence-document type is a possible later cleanup, not a v0.4 requirement.

---

## 10. Next phase: empirical validation

v0.4 is feature-complete. The next work is measurement:

1. build/freeze a labelled benchmark corpus;
2. measure the deterministic lane separately;
3. measure the semantic judge separately;
4. measure the combined system;
5. characterize false positives and false negatives by invariant/finding type;
6. calibrate low/medium/high/critical thresholds;
7. retain every meaningful misclassification as a reproducible case.

The framework is now mature enough to be tested. The next credibility gain comes from empirical performance, not additional conceptual surface area.
