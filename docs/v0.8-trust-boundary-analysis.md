# v0.8 Trust-Boundary Analysis

**Status:** implemented contract

## 1. Purpose

v0.8 detects structural authority crossings in validated v0.6 inventory
artifacts. It does not decide whether content is malicious, suspicious, safe, or
well-intentioned. It performs no retrieval, execution, exploitation, LLM
judgment, or prompt-injection analysis.

The offline flow is:

```text
validated inventory -> authority extraction -> boundary classification
                    -> v0.5 FindingContract records
```

The explicit CLI is:

```text
semantic-intent trust-analyze inventory.json
```

## 2. Trust model

| Term | Deterministic meaning in v0.8 |
|---|---|
| `origin` | Canonical origin of the authority-source resource. |
| `authority source` | A retrieved manifest or API schema containing a supported authority-bearing declaration. |
| `target` | The canonical schema or capability URL named by that declaration. |
| `boundary` | Equality or inequality of canonical source and target origins, including effective port. |

Canonical URL and origin handling is imported from v0.6. v0.8 does not maintain
a parallel normalization implementation.

## 3. Supported authority edges

Only structures that v0.6 preserves unambiguously are authority-bearing.

| Source surface | Preserved declaration | Target | Relationship type |
|---|---|---|---|
| `ai_manifest` | `api.url` | `api_schema` | `action_schema_delegation` |
| `ai_manifest` | `mcp_endpoint` | `advertised_endpoint` | `capability_delegation` |
| `ai_manifest` | `agent_endpoint` | `advertised_endpoint` | `capability_delegation` |
| `api_schema` | `servers[].url` (`endpoint_kind: openapi_server`) | `advertised_endpoint` | `capability_delegation` |

An extracted edge retains source surface identity, declaration path, declaring
and target canonical origins, target URL, relationship type, inventory
provenance, and boundary classification. Findings expose these facts through
the existing v0.5 evidence and `context.authority_edge` fields; no finding-schema
change is needed.

The following are deliberately not authority assertions:

- `robots.txt` sitemap declarations;
- ordinary sitemap links;
- surface existence;
- generic manifest `url` or `endpoint` fields, whose semantics are ambiguous;
- arbitrary links or metadata;
- inventory changes from v0.7.

The inventory does not preserve a structured explicit-trust or authentication
declaration. v0.8 therefore cannot suppress a crossing based on one and does not
invent a substitute. It also cannot establish data-to-instruction elevation from
llms text because inventory artifacts contain observations, not document bodies.

## 4. Boundary taxonomy

| Classification | Rule | Finding behavior |
|---|---|---|
| `same_origin` | Source and target have equal canonical scheme, host, and effective port. | No cross-origin finding. |
| `cross_origin` | Canonical scheme, host, or effective port differs. | Emit the applicable structural finding. |

All valid v0.6 inventory URLs are HTTPS. A scheme difference involving a
non-HTTPS URL is malformed inventory and fails validation rather than becoming a
finding. Host case, one DNS root trailing dot, IDNA, default port 443, fragments,
and dot segments have already been normalized by v0.6. Explicit non-default
ports remain part of the origin boundary.

Cross-origin alone is not a finding. A finding requires both a supported
authority edge and a cross-origin classification.

## 5. Findings and severity

v0.8 uses the existing v0.5 `FindingContract` schema `0.1` directly.

### `cross_origin_action_schema_delegation`

A manifest delegates definition of agent-available actions to `api.url` on a
different origin. The structural issue is the authority delegation, not the
existence or content of the schema.

### `cross_origin_capability_delegation`

A manifest or action schema delegates an explicit MCP, agent, or OpenAPI server
capability to a different origin. Generic endpoint metadata does not qualify.

Both findings map to invariant I8 and severity `low`. The classification is
conservative: the edge establishes a cross-origin authority
dependency, but v0.8 has no evidence of exploitation, malicious content,
privilege level, or intent. No new scoring system or legacy risk aggregation is
introduced.

I8 is the established fit because it governs extending trust from retrieved
content to named external tools and resources before an explicit trust decision.
I6 concerns suppression of logs or auditability and is not used here. Severity
is a fixed `low` mapping for these two structural types; no dynamic weighting or
legacy aggregate-risk integration occurs.

Each finding records:

- the structural source, declaration path, target, and boundary;
- why independent authority across that boundary matters;
- the outcome that authority is either origin-constrained or independently
  established;
- a declarative retest that the unsupported cross-origin delegation is absent.

## 6. Validation and determinism

The analyzer accepts only inventory schema `0.1` artifacts that pass the v0.6
validator. Unsupported versions, malformed URLs, duplicate surface identities,
unresolvable declaring surfaces, contradictory source types, malformed supported
authority metadata, and duplicate authority edges fail closed.

Inputs are copied and never mutated. Edges and findings are sorted by source,
relationship, declaration path, and target. Identical inputs produce
byte-for-byte identical serialized findings.

## 7. Examples

A manifest on `https://example.com` declaring
`https://api.example.net/openapi.json` through `api.url` produces
`cross_origin_action_schema_delegation`.

The same declaration targeting `https://example.com/openapi.json` produces no
cross-origin finding. A sitemap linking to either URL also produces no finding,
because sitemap discovery does not grant action authority.

## 8. False-positive constraints

- A cross-origin link is not enough.
- A manifest, schema, or endpoint existing is not enough.
- A content or data dependency is not enough.
- A v0.7 addition or change is not enough.
- Only the supported declaration paths in section 3 create authority edges.

## 9. Explicit non-goals

No prompt-injection detection, semantic maliciousness classification, active
retest, model judgment, crawler expansion, live network access, execution,
exploitation, behavioral sandbox, persistence, autonomous remediation, or
ethical-guardian policy is part of v0.8.
