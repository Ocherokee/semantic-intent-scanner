# v0.6 Agent-Readable Attack-Surface Inventory

**Status:** implemented design and contract

**Inventory schema version:** `0.1`

## 1. Purpose

The v0.6 inventory enumerates public, machine-readable surfaces that an
autonomous agent could encounter. Each entry states what resource was observed,
where it was declared, how it was discovered, whether retrieval succeeded, and
factual transport or metadata properties.

Inventory is not analysis. An entry does not claim that a resource is unsafe,
malicious, excessive, exploitable, or evidence of a failed trust boundary.
Existing scanners may independently produce established findings while handling
the same resource; v0.6 neither creates nor suppresses those findings.

## 2. Architecture

`scanner.surface_inventory` is a sibling to the existing remote-analysis
adapters. It reuses `remote_fetch.guarded_fetch` and returns one canonical
inventory representation. It does not call `analyze_document`, the semantic
judge, registry lookups, or any finding serializer.

The explicit additive interface is:

```text
semantic-intent inventory https://example.com
```

It emits only the v0.6 JSON inventory envelope. Existing `scan`, `scan-remote`,
and `scan-mcp` terminal and JSON formats are unchanged.

## 3. Surface taxonomy

| `surface_type` | Meaning | Retrieval behavior |
|---|---|---|
| `robots` | Root `/robots.txt` resource. | Fixed seed; retrieved through the guarded fetcher. |
| `llms` | `/llms.txt` or `/llms-full.txt`, the variants already recognized by the scanner. | Fixed scanner-known seeds; retrieved. |
| `sitemap` | XML sitemap or sitemap index explicitly declared by `robots.txt` or another sitemap. | Same-origin declarations are retrieved within bounds. |
| `ai_manifest` | Machine-readable AI/agent manifest at a recognized manifest path. | `/.well-known/ai-plugin.json` is a fixed well-known seed; other recognized manifests must be declared. |
| `api_schema` | Public OpenAPI/Swagger schema explicitly declared by a manifest or sitemap. | Same-origin declarations are retrieved within bounds. |
| `advertised_endpoint` | MCP, agent, or API endpoint explicitly named by an already retrieved manifest or API schema. | Recorded as advertised; never contacted by v0.6. |

Recognized declared manifest basenames are `ai-plugin.json`, `agent.json`, and
`mcp.json` under `/.well-known/`. Recognized schema basenames are
`openapi.json`, `openapi.yaml`, `openapi.yml`, `swagger.json`, `swagger.yaml`,
and `swagger.yml`. v0.6 does not guess arbitrary API, MCP, or agent paths.

## 4. Discovery provenance

Every entry contains one or more `discovery` records. Records are kept distinct
and sorted deterministically; discovering one resource twice does not collapse
the mechanisms into a generic “found” flag.

| `kind` | Meaning |
|---|---|
| `well_known_path` | Seeded from a public well-known convention (`robots.txt` or `ai-plugin.json`). |
| `scanner_known_path` | Seeded from an existing scanner-supported path (`llms.txt` variants). |
| `robots_declaration` | Declared by a `Sitemap:` line in retrieved `robots.txt`. |
| `sitemap_declaration` | Declared by a `<loc>` in a retrieved sitemap or sitemap index. |
| `manifest_declaration` | Explicitly named by a retrieved AI/agent manifest. |
| `schema_declaration` | Explicitly named by a retrieved API schema. |

Each record contains the declaring `source_url` except for fixed seeds.

## 5. Bounded discovery rules

v0.6 is intentionally not a crawler.

- **Fixed seeds:** exactly `/robots.txt`, `/llms.txt`, `/llms-full.txt`, and
  `/.well-known/ai-plugin.json`, resolved from the supplied HTTPS origin.
- **Maximum inventory entries:** 32, including seeds, retrieved declarations,
  advertised endpoints, failures, and blocked resources.
- **Maximum declaration depth:** 2 edges from a fixed seed. A discovered entry
  at depth 2 is recorded but its content cannot add further entries.
- **Follow rules:** only recognized surface types are added. Ordinary sitemap
  page URLs and arbitrary JSON links are ignored.
- **Same-origin retrieval:** only resources with the same scheme, normalized
  hostname, and effective port as the target origin are fetched. Explicit port
  changes are different origins. Cross-origin declarations are recorded with
  status `advertised` and are not contacted.
- **Redirects:** followed and validated only by `guarded_fetch`. Same-origin
  restrictions apply to declared request targets; the existing fetcher may
  follow a validated public cross-origin redirect, which is explicitly recorded
  in the entry. No inventory-specific redirect implementation exists.
- **Body and transport limits:** the existing guarded-fetch timeout, redirect
  ceiling, SSRF checks, pinned-IP transport, decompressed 512 KiB body cap, and
  truncation flag apply unchanged.
- **Cycles and duplicates:** canonical URL plus surface type identifies an
  entry. Duplicate declarations merge provenance and relationships. A resource
  is fetched at most once. Cycles therefore terminate without special probing.
- **Fragments:** removed during canonicalization. Scheme and hostname are
  lowercase; default HTTPS port 443 is omitted; non-default explicit ports and
  query strings are preserved.
- **Malformed metadata:** the retrieved entry remains factual and carries a
  bounded `parse_error`; malformed content does not produce child entries.

## 6. Canonical inventory contract

The inventory version is independent of the scanner package version, legacy
report version, and v0.5 finding schema version.

### 6.1 Envelope

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `inventory_schema_version` | string | yes | Exactly `"0.1"` in v0.6. |
| `target_origin` | HTTPS URL string | yes | Canonical origin supplied for discovery. |
| `entries` | array | yes | Canonical entries in deterministic order. |
| `truncated` | boolean | yes | True when the 32-entry ceiling prevented an additional recognized entry. |

### 6.2 Entry

| Field | Type | Required | Meaning |
|---|---|---:|---|
| `schema_version` | string | yes | Entry schema version, `"0.1"`. |
| `surface_type` | string | yes | One taxonomy value from §3. |
| `resource_url` | HTTPS URL string | yes | Canonical requested or advertised resource. |
| `discovery` | non-empty array | yes | Distinct provenance records from §4. |
| `observation` | object | yes | Retrieval or advertisement facts. |
| `relationships` | array | yes | Factual typed links to declaring resources. |
| `metadata` | object | yes | Bounded factual metadata; empty when none is available. |

`observation.status` is one of `retrieved`, `not_found`, `blocked`, `failed`, or
`advertised`. A retrieved observation may include final URL, HTTP status,
content type, hash, timestamp, redirect chain, origin-change flag, and
truncation. Failed or blocked observations preserve the existing fetcher's error
or blocked reason.

Relationships use `declared_by` and the canonical URL of the declaring
resource. They do not express trust or legitimacy.

Unknown fields, unsupported versions, malformed nested structures, non-JSON
values, and non-finite numbers fail validation. Validation never fills missing
fields or interprets metadata.

## 7. Parsing and metadata

- `robots.txt`: only case-insensitive `Sitemap:` declarations are parsed.
- Sitemaps: only XML `<loc>` text is considered. Both sitemap indexes and URL
  sets are accepted; ordinary page URLs are ignored unless their path is a
  recognized inventory surface.
- AI plugin manifests: only bounded scalar fields (`name_for_model`,
  `description_for_model`, `schema_version`) and explicit `api.url` are used.
- Other recognized manifests: only explicit scalar URL fields named
  `mcp_endpoint`, `agent_endpoint`, `endpoint`, or `url` are used.
- JSON API schemas: only `servers[].url` is used to record advertised endpoints.
- YAML is inventoried and retrieved when declared, but v0.6 does not add a YAML
  parser; no endpoints are derived from YAML content.
- Metadata strings are capped at 512 characters and collection sizes at 16
  items. These caps prevent a small public document from expanding the
  inventory representation without bound.

## 8. Example

```json
{
  "inventory_schema_version": "0.1",
  "target_origin": "https://example.com",
  "entries": [
    {
      "schema_version": "0.1",
      "surface_type": "llms",
      "resource_url": "https://example.com/llms.txt",
      "discovery": [
        {"kind": "scanner_known_path"}
      ],
      "observation": {
        "status": "retrieved",
        "final_url": "https://example.com/llms.txt",
        "http_status": 200,
        "content_type": "text/plain",
        "fetched_at": "2026-08-29T12:00:00Z",
        "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
        "redirect_chain": [
          {"url": "https://example.com/llms.txt", "status": 200}
        ],
        "cross_origin_redirect": false,
        "truncated": false
      },
      "relationships": [],
      "metadata": {}
    }
  ],
  "truncated": false
}
```

The example says only that the known resource returned plain text. It makes no
claim about the text's intent, safety, or authority.

## 9. Compatibility and use

- Existing scan commands and reports are unchanged.
- Inventory output is additive and has its own command and version domain.
- v0.5 `FindingContract` schema `0.1` is unchanged. Inventory entries are not
  findings and cannot be passed to finding serializers without an explicit,
  future analysis decision.
- Machine consumers should branch on `inventory_schema_version`, validate the
  envelope, and treat `advertised` resources as observed declarations rather
  than successful retrievals.

## 10. Explicit non-goals

No prompt-injection detection, risk scoring, capability judgment, vulnerability
claim, privileged interaction, exploitation, command execution, instruction
following, general crawling, ethical-guardian policy, registry provenance
analysis, or active retest machinery is part of v0.6.
